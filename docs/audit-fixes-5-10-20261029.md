## Approved decisions

## Implemented

5–6. Product pages now link to Inventory. Each receipt is one Product batch with
required purchase unit cost, draft estimated amount and confirmed actual amount.
Creating a Product remains zero-stock. Drafts leave stock unchanged; QC rejection
determines accepted stock and cost. Manual decrease/issue creation and confirmation
controls removed from UI; historical issue records and legacy backend contract retained.
Old receipts retain unknown price instead of invented zero. Decimal strings and
BigInt formatting avoid rounding large whole-VND batch totals.

7. Checkout uses the shared visible Button for both voucher actions. Input shrinks
on narrow screens; button stays readable. Price-voucher feedback is associated
with the input, announced, and cleared when the code changes.

8. CustomerLayout owns cart visibility. Opening the cart closes customer chat and
removes its floating widget until the cart closes. Existing focus containment,
body scroll lock and selected-item checkout remain in place.

9. Added paged ASSIGNED queue and POST /chat/conversations/{id}/take-over with
expectedStaffId. The service locks the active actor/conversation and rejects stale
assignees or closed chats with 409. Existing ownership checks protect every read,
send and close; the old staff gets an in-app notice. Frontend clears a revoked
thread on 403. No offline timer or fabricated presence state is introduced.

10. Removed staff dashboard current-shift badge and StaffLayout online-shift badge.
Admin header has no ready-system badge; its stale comment was cleaned up.

Browser QA also found and fixed a pre-existing white-screen bug: changing inventory
views briefly rendered stock balances as documents, causing Invalid time value.
The table now renders only data loaded for its current view.

## Second review, 2026-10-29

Found and corrected three remaining frontend edge cases:

- Receipt estimate and submission used different numeric validation. Native number
  fields accept integer-valued entries such as `5e1` and `120000.0`, but the preview
  rejected their spelling. Both now use the same validated numeric values before
  exact BigInt multiplication; requiredness and approved bounds are preserved.
- Inventory rendering now identifies the completed request by view, page, filters,
  product and refresh. Previous rows/actions are hidden while any of these change.
  Failed requests complete normally and show retry instead of indefinite loading.
- Takeover confirmation captures the conversation/assignee when opened. A queue
  refresh cannot silently change the expected assignee at confirmation. A 409 clears
  the stale selection and refreshes the queue. Send/close 403 responses immediately
  clear the selected thread and composer. Older-message pagination also handles
  revoked access, including when live polling is disabled.
