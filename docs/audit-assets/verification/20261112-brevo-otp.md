# Brevo OTP verification — 2026-11-12

User selected Brevo for the registration OTP delivery issue after confirming
Railway Free/Trial/Hobby, which blocks SMTP. This record covers the final Brevo
implementation and does not claim live delivery from earlier transport options.

## Final change

- Existing `EmailOtpNotifier` boundary selects `brevo` or the existing `gmail`
  SMTP default via conditional Spring beans. Exactly one provider is instantiated.
- Brevo uses the fixed HTTPS transactional email endpoint with an `api-key`
  header, sender/recipient objects, and the existing Vietnamese text/HTML message.
  The template is shared, avoiding duplicated content across transports.
- API configuration is backend-only. `prod` validates the selected provider and
  Brevo does not require SMTP credentials. SMTP keys beginning `xsmtpsib-` are
  rejected explicitly; they cannot authorize Brevo REST email calls.
- Five-second connection and ten-second response limits; redirects disabled and
  no automatic retries. Acceptance requires a nonblank `messageId`. Errors and
  malformed responses become a safe 503. Logs include only HTTP status/category.
- No API key, provider body, recipient or OTP is logged or returned in errors.
  No dependency, schema, frontend, customer Google-login or account/OTP/session
  lifecycle change. Existing OTP service rollback and reset-enumeration rules
  remain authoritative. POS invoice SMTP transport is a separate scope.
- Setup: [BREVO_OTP_DEPLOYMENT.md](../../BREVO_OTP_DEPLOYMENT.md).

## Live configuration status

The saved private backend `.env` was rechecked after the user's update. The
`BREVO_API_KEY` variable and sender now exist, but the key is still an SMTP key
(`xsmtpsib-`), so the preflight deliberately did not send it to the REST API or
send a test email. The user was directed to Brevo's API Keys tab to replace it.
No secrets are included in this record or repository.

Production activation still requires the REST API key, a verified/active sender,
the new backend deployment and these Railway variables: `OTP_EMAIL_ENABLED`,
`OTP_EMAIL_PROVIDER`, `BREVO_API_KEY`, `OTP_EMAIL_FROM`. Local `.env` changes do
not update Railway. Actual inbox receipt and successful OTP verification have
not yet been observed. Do not report the production incident resolved until they are.
