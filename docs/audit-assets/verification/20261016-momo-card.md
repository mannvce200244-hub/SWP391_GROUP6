# MoMo hosted card sandbox — 2026-10-16

## Approved change

The user requested credit-card payment through the official MoMo sandbox.
Creation now uses `payWithCC`, signs that exact request type, and supplies
`userInfo.email` from the persisted order recipient email. Whole-VND amounts
are restricted to 1,000–10,000,000 inclusive, as required by the
[official card API](https://developers.momo.vn/v3/vi/docs/payment/api/credit/onetime/).
Checkout identifies the option as international-card sandbox payment.

## Runtime and limits

The old frontend tunnel was no longer running. Its replacement is
`https://pdt-impaired-valid-clocks.trycloudflare.com`; ignored local configuration
now uses its exact host/origin and `/payment-return`. Backend IPN remains
`https://flex-conflict-bass-feeds.trycloudflare.com/api/v1/payments/momo/ipn`.
Quick tunnel addresses are temporary and require running tunnel processes.

Existing pending attempts retain their saved URL to prevent duplicate charge
sessions. New attempts use cards. URL creation does not establish payment;
backend verification of provider results remains required. No full card charge,
3DS, return/IPN completion, or refund was executed during this check.

Security review: card details stay on MoMo; credentials stay in the ignored
backend environment; TLS endpoint and redirect allowlist remain fixed; HMAC
and ownership, persisted amount, pending-attempt and refund safeguards remain.
No dependency or public M4N API contract changed. The existing oversized
CheckoutPage received only payment label/description edits; no new component
or broad refactor was introduced.
